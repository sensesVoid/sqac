# SQAC v1.1.0 Track C Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the v1.1.0 feature bundle — agent-cartridge encryption (opt-in), multi-vault support, external secret providers (1Password + Bitwarden CLI wrappers), a blocking performance gate, a docs site, and package hygiene — in one additive release.

**Architecture:** Six goals sequenced by dependency: hygiene (pure moves) → multi-vault (foundation) → providers (binds to named vaults) → agent encryption (reuses keychain patterns) → perf gate (needs a recorded baseline) → docs site (last, nav final once docs settle). No new crypto; reuse `vault_crypto`. No new runtime dependencies; providers are subprocess CLIs.

**Tech Stack:** Python 3.10+ (existing), numpy (existing), cryptography (existing), MkDocs Material (docs-site CI only), cibuildwheel (existing).

**Spec:** `docs/superpowers/specs/2026-11-16-sqac-v1.1-design.md`

## Global Constraints

- Zero new runtime dependencies (providers are subprocess CLIs; docs site is a repo concern).
- Backward compatible: existing plaintext agents and single default vault keep working unchanged; old vault refs (`vault:NAME`) keep resolving.
- Windows/macOS/Linux parity for every new CLI path (no Unix-only imports; guard with `try/except ImportError`).
- Agent encryption is never default-on; plaintext agents stay first-class.
- Cloud secret-manager APIs deferred — only 1Password + Bitwarden CLI wrappers in 1.1.0.
- Version: **1.1.0** (additive, backward compatible).

## Review Focus

- A user on Windows with no `op`/`bw` CLI installed runs `sqac vault init --provider 1password` — the error must name the missing CLI and how to install it, not a traceback.
- An encrypted agent cartridge opened with the wrong passphrase/keychain entry must fail loudly (decryption error), never silently return garbage or partial plaintext.
- A `vault:FOO/bar` ref pointing at a non-existent vault FOO must raise a clear "vault not found" error, not create an empty vault.
- Cross-vault ciphertext must fail the AAD check (copying an entry from vault A into vault B must not decrypt).
- The perf gate must not flake on runner noise: median-of-3, 20% threshold, documented tolerance.
