# SQAC v1.2 Design — Secret Domain, Agent Binding, and Sync Policy

**Date:** 2026-11-16  
**Status:** Draft (proposal for Genos integration)  
**Base:** SQAC v1.0.0 (released), v1.1.0 Track C (agent encryption, multi-vault, 1Password/Bitwarden providers, perf gate, docs site)  
**Related:** `C:\Users\geral\genos\docs\PRD-Genos.md`, `C:\Users\geral\genos\docs\DesignDoc-Genos.md`

## 1. Intent and why

Genos (a local-first, Jarvis-like assistant built on SQAC) needs a clean boundary between **what an agent is**, **what secrets it may use**, and **what must never leave the machine**. Today SQAC provides the primitives but not the binding:

- **Vault cartridges** (`cartridge_type: vault`, v5) store encrypted secrets and support keychain/Argon2id + 1Password/Bitwarden providers. They are the right place for raw secret material and backend-only `vault exec`/resolution.
- **Agent cartridges** (`cartridge_type: agent`) store persona and working state (identity, instruction, preference, goal, decision, note) with opt-in AES-256-GCM encryption (v1.1.0).
- **Cloud sync** pushes/pulls allowlisted cartridge families to S3-compatible storage (Cloudflare R2 etc.), but policy is path-based and coarse (keychain vaults excluded; agents/vault dirs currently in the always-sync allowlist).

What is missing: a **Secret Domain** that holds *references and metadata* (never raw values) an agent is allowed to use, an explicit **Agent↔Secret/Model binding** in the agent schema, and a **cartridge-level sync policy** that makes “never sync secrets/agents” enforceable by the sync engine rather than by convention.

This spec closes that gap so Genos P0–P2 can ship with a single, auditable secret-resolution path and a safe Cloudflare sync story for non-secret cartridges.

## 2. Goals

- **G1 — Secret Domain cartridge type.** A first-class `cartridge_type: "secret"` cartridge that stores **references and metadata only** (no raw secret values). Entries point to Vault entries and/or external providers (`vault:...`, `op://...`, `bw:...`) with labels, tags, policy hints, and timestamps.
- **G2 — Agent schema v2 binding.** Agent header extra gains stable binding fields: `model_profile_id`, `secret_ref` (or `secret_refs`), and optional `allowed_tools`/capability tags, so the Genos backend can resolve “which model + which secrets this agent may use” from the agent record alone.
- **G3 — Cartridge sync policy.** A self-describing `sync_policy` in cartridge header extra (`write_through` | `never` | `local_only`) enforced by the cloud sync engine. Defaults: `agent` and `secret` and `vault` → `never`; `memory/facts/skills/docs` → `write_through`. Policy is checked on push, pull, and status.
- **G4 — Backend-only SecretResolver.** A resolver API (library + reference pattern for Genos HTTP backend) that resolves secret refs to plaintext **only inside the trusted backend process**, never returning values to UI, never logging values, and emitting audit events (ref used, not value).

## 3. Non-goals

- No new cryptographic primitives. Reuse `vault_crypto` (AES-256-GCM, Argon2id), existing keychain integration, and existing 1Password/Bitwarden provider wrappers.
- No raw secret storage in the Secret Domain. Secret Domain entries are pointers/metadata; raw values live in Vault cartridges or external providers.
- No Genos UI implementation in this spec (Genos owns UI). This spec defines the SQAC contracts the UI will consume.
- No automatic Cloudflare sync for Secret Domain, Vault, or Agent cartridges. These are explicitly non-syncable by default.
- No multi-tenant/hosted SaaS secret sharing model in v1.2.

## 4. Anti-goals (failure modes)

- **Secret leakage:** raw secret values written into `fact`/`skill`/`doc`/`turn`/agent memory entries, logged, included in prompts as unredacted context, returned to UI, or pushed to Cloudflare.
- **Silent policy bypass:** a cartridge with `sync_policy: never` being pushed/pulled because path allowlists took precedence.
- **Ambiguous resolution:** a `secret_ref` that could resolve to different secrets depending on ambient state without an explicit, auditable resolution chain.
- **Breaking existing cartridges:** v1.0/v1.1 agents, vaults, and memory cartridges must continue to load and operate unchanged.

## 5. Constraints

- Backward compatible and additive. No breaking changes to existing cartridge formats or public APIs.
- Zero new runtime dependencies for core SQAC. (Providers remain subprocess CLI wrappers; cloud remains boto3-optional as today.)
- Windows/macOS/Linux parity for CLI and resolution paths.
- Secrets resolved only in the backend/trusted process. MCP and HTTP surfaces remain **reference-only** for secret values (metadata, audit, proxy/exec patterns) unless an explicit, opt-in, audited backend-internal path is used — never a “return plaintext secret to arbitrary caller” tool.
- Align with Genos locked decisions: orchestrator/decision local; secrets local-controlled; Cloudflare for non-secret cartridges only.

## 6. Current state (baseline)

| Component | State (v1.0.0 / v1.1.0) |
|---|---|
| Vault | `cartridge_type: vault`, v5 encrypted entries, AES-256-GCM DEK wrap, keychain/Argon2id/passphrase, `vault exec`, audit, PII scan, MCP reference-only tools, 1Password/Bitwarden provider fetch for master key (v1.1.0), multi-vault registry + `vault:VAULT/NAME` refs (v1.1.0) |
| Agent | `cartridge_type: agent`, schema 1, sections identity/instruction/preference/goal/decision/note, bootstrap packet, opt-in file-level encryption SQAE (v1.1.0) |
| Cloud sync | Path allowlist (`facts, skills, docs, agents, vaults` always; continuity/archives opt-in), keychain vaults skipped, ETag-based conflict detection, no header `sync_policy` |
| Secret resolution | Vault `resolve(name)` and `exec_env`; providers `fetch(provider, ref)`; no unified Secret Domain indirection |

## 7. Approaches considered

### 7.1 Secret Domain representation

- **A1 (chosen): Dedicated `cartridge_type: "secret"` cartridge.** Stores a registry of named secret references and metadata (provider/vault/ref, description, tags, policy, timestamps). May itself be encrypted at rest (recommended) using the same vault/agent crypto patterns. Never stores raw secret values. Distinct from `vault` so “secret material” (vault) and “secret entitlements/refs for agents” (secret domain) have different lifecycles and sync policies.
- **A2 (rejected): Reuse `vault` type for both.** Conflates encrypted secret storage with reference/entitlement mapping; harder to express “this agent may use these refs” without exposing vault structure.
- **A3 (rejected): Plain entries in memory cartridges.** Violates the core security boundary — refs/metadata would mix with recallable memory and risk sync/leakage.

### 7.2 Agent binding

- **B1 (chosen): Extend Agent header extra (schema v2).** Add `model_profile_id`, `secret_ref` (single) and/or `secret_refs` (list), `allowed_tools`, and `sync_policy` awareness. Agent records remain the single source of truth for “who this agent is and what it may access.”
- **B2 (rejected): Separate binding cartridge/file.** Extra indirection and drift risk; Genos needs one lookup to load an agent profile.

### 7.3 Sync policy enforcement

- **C1 (chosen): `extra.sync_policy` as the authoritative per-cartridge policy, enforced in `SyncEngine`.** Policy read from header (cached per path during a sync run). Path allowlists become *eligibility* filters; `sync_policy: never|local_only` is a hard deny regardless of path. Defaults derived from `cartridge_type` when field absent.
- **C2 (rejected): External policy config only.** Not portable with the cartridge; easy to misconfigure across machines.
- **C3 (rejected): Rely on path allowlists only.** Too coarse; cannot express “this specific cartridge must never sync” and currently allows `agents/` and `vaults/` dirs by default.

## 8. Design (decided)

### 8.1 Cartridge sync policy

**Header field:** `extra.sync_policy` (string, optional)

| Value | Meaning |
|---|---|
| `write_through` | Eligible for cloud sync subject to existing allowlist/opt-in rules and credential/keychain constraints |
| `never` | Must not be pushed, pulled, or reported as syncable to cloud under any circumstance |
| `local_only` | Alias for `never` for v1.2 (reserved for future “local-network sync only” semantics; treated as never by cloud engine) |

**Effective defaults when `sync_policy` is absent:**

| `cartridge_type` / context | Default |
|---|---|
| `secret` | `never` |
| `vault` | `never` (defense-in-depth; keychain vaults also remain non-syncable) |
| `agent` | `never` (Genos assumption: agent profiles are sensitive unless explicitly opted in later — see open question) |
| memory / facts / skills / docs / other | `write_through` |

**Sync engine changes (`sqac/cloud.py`):**

- Add `_effective_sync_policy(path: Path) -> str` that reads `read_cartridge(path).header.extra.get("sync_policy")` and falls back to type-based defaults; on read error, fail closed to `never`.
- `_is_syncable(rel)` remains the path/allowlist gate. A cartridge is sync-eligible only if `_is_syncable(rel)` **and** `_effective_sync_policy(full_path) == "write_through"` (and existing keychain-vault check still applies).
- `status()`, `push()`, `pull()` must all apply the same effective-policy check so a `never` cartridge cannot be surfaced as pushable/pullable.
- Conflicts involving a `never` policy resolve to `skip` with reason `sync_policy_never` (never overwrite local sensitive state from remote).

**CLI:** `sqac cloud status` should display effective policy per object; `sqac cloud push/pull` must refuse policy-denied objects with a clear reason (not a generic error).

### 8.2 Secret Domain cartridge (`cartridge_type: "secret"`)

**Purpose:** A portable, queryable registry of secret *references* an application/agent is authorized to use. The Secret Domain does **not** contain secret plaintext.

**Storage/layout:** Implemented as an encrypted-capable cartridge using the existing format/vault-crypto patterns (recommended: v5-style encrypted entries or agent-style encrypted file envelope — **left to builder**, but must meet the same at-rest protection bar as Vault/Agent when encryption is enabled). Default on-disk location (suggested): `~/.sqacm/secrets/<name>.sqac` managed by a small registry analogous to `VaultRegistry`.

**Header extra:**

```json
{
  "cartridge_type": "secret",
  "sync_policy": "never",
  "secret_domain": {
    "schema": 1,
    "name": "default",
    "created": "...",
    "updated": "..."
  },
  "encrypted": true
}
```

**Entry model (metadata only):**

| Field | Type | Required | Notes |
|---|---|---|---|
| `name` | string | yes | Stable key within the domain (e.g. `openrouter_api_key`) |
| `ref` | string | yes | Resolution target: `vault:NAME`, `vault:VAULT/NAME`, `provider:1password:op://...`, `provider:bitwarden:...` (exact URI scheme finalized by builder, but must be unambiguous and auditable) |
| `description` | string | no | Human label for UI (non-secret) |
| `tags` | list[string] | no | e.g. `["llm","openrouter"]` |
| `scopes` | list[string] | no | Optional allowed use hints (e.g. hosts/tools) |
| `created` | string | yes | ISO-8601 UTC |
| `updated` | string | yes | ISO-8601 UTC |

**Invariants:**
- No raw secret values in any field. Content validation SHOULD reject values that look like credentials/high-entropy secrets (reuse `sqac.credentials` / PII heuristics where sensible).
- `name` is unique within a domain; updates replace metadata for the same name.
- Listing/reading returns metadata only.

**API (library):** `SecretDomain` (or equivalent) with `create/open`, `put_ref`, `get_ref_meta`, `list`, `remove`, `rename` — mirroring Vault/Agent ergonomics but reference-only.

**CLI (proposed):** `sqac secret init|list|put-ref|get-meta|rm` with `--domain` analogous to `--vault`. All commands print metadata only; no command prints resolved plaintext.

**MCP:** reference-only tools (`secret_list`, `secret_meta`) — no plaintext retrieval.

### 8.3 Agent schema v2 (binding)

**Header extra (additive):**

```json
{
  "cartridge_type": "agent",
  "sync_policy": "never",
  "agent": {
    "schema": 2,
    "name": "jarvis",
    "role": "assistant",
    "model_profile_id": "openrouter-claude-3.5-sonnet",
    "secret_ref": "secret:default/openrouter_api_key",
    "secret_refs": ["secret:default/openrouter_api_key"],
    "allowed_tools": ["mem_search", "mem_write", "ast_explore"],
    "created": "...",
    "updated": "..."
  }
}
```

**Field semantics:**
- `model_profile_id` (string, optional): opaque ID resolved against the **Genos config store** (local, non-secret). SQAC stores the ID; Genos owns model profile records.
- `secret_ref` (string, optional): primary secret reference for convenience/back-compat.
- `secret_refs` (list[string], optional): explicit set of allowed secret refs. If both present, they must be consistent (`secret_ref` included). Resolution outside this set SHOULD be denied by the resolver when an agent context is provided.
- `allowed_tools` (list[string], optional): advisory allowlist surfaced to Genos policy; enforcement is in Genos orchestrator, but the field lives with the agent.

**Migration:**
- `AgentCartridge.load` accepts schema 1 and treats missing binding fields as `null/[]`.
- On next save, write schema 2 preserving all existing fields/sections; never drop data.
- Existing encrypted agents (v1.1.0 SQAE envelope) remain loadable; schema bump is in header extra inside the cartridge payload.

**Helpers:** `agent.set_binding(model_profile_id=..., secret_ref=..., secret_refs=..., allowed_tools=...)` and corresponding CLI flags/subcommands (`sqac agent bind ...`, or `agent create --model-profile --secret-ref ...`).

### 8.4 Backend-only SecretResolver (Genos integration contract)

**Location:** Reference implementation/prototype in Genos backend (`genos/backend/secret_resolver.py`); SQAC may later expose a library helper, but the trust boundary is the backend process.

**Responsibilities:**
1. Accept a ref string and optional agent context.
2. Parse ref kind: direct `vault:` / `vault:VAULT/NAME`, `provider:*` (1P/BW/…), or `secret:<domain>/<name>` (indirection via Secret Domain).
3. If agent context provided, enforce that the ref is permitted by `secret_refs`/policy (fail closed).
4. Resolve to plaintext using local `VaultRegistry`/`Vault.open(...).resolve(...)` and/or `sqac.providers.fetch(...)` **in-process**. Never via a network call that would expose plaintext to an untrusted peer.
5. Return plaintext to the caller (backend) only; emit an **audit event** `{ts, agent, ref_kind, ref_id (not value), outcome}` to a local audit log.
6. Zeroize/avoid retaining values longer than necessary (best-effort in Python).

**Non-exposure guarantees (contract):**
- Resolver MUST NOT log secret values.
- Resolver MUST NOT return values over HTTP/MCP responses to UI clients.
- Genos provider adapters receive resolved credentials only at call time and must not persist them.

**Example resolution chains:**

- `vault:openrouter` → active/default vault → entry `openrouter`
- `vault:prod/openrouter` → vault `prod` → entry `openrouter`
- `secret:default/openrouter_api_key` → Secret Domain `default` metadata `ref` → (e.g.) `vault:prod/openrouter` → plaintext (backend-only)
- `provider:1password:op://Private/OpenRouter/api_key` → `sqac.providers.fetch("1password", ...)`

### 8.5 Cloudflare sync policy adapter (implementation)

**SQAC core (preferred, v1.2):** enforce policy inside `SyncEngine` as in §8.1. This is the authoritative fix.

**Genos-side adapter (immediate, works against v1.0/v1.1):** a `PolicyAwareSyncEngine` wrapper/subclass usable by Genos before upgrading SQAC, implementing the same effective-policy logic:

- During `status/push/pull`, for each candidate object: read cartridge header if the file is a `.sqac`; compute effective policy from `extra.sync_policy` or `cartridge_type` default; skip with reason `sync_policy_never` when not `write_through`.
- Treat unreadable/corrupt headers as `never` (fail closed).
- Never upload/download files under `secrets/` by default unless policy explicitly allows (and v1.2 forbids it).

A reference implementation is provided in `C:\Users\geral\genos\prototypes\sync_policy_adapter.py`.

### 8.6 Prompt-injection and trust (Genos-facing note)

Not a new SQAC subsystem in v1.2, but required by Genos: retrieved SQAC content (facts/docs/turns/graph nodes) is **untrusted input**. Genos must:
- Surface SQAC trust/risk signals in UI when available.
- Wrap retrieved text as untrusted context in prompts (delimiters, instructions to ignore embedded directives).
- Keep Secret Domain refs/metadata separate from recallable memory content.

## 9. Security model

- **At rest:** Vault and Secret Domain encrypted when configured (keychain/Argon2id); Agent encryption opt-in (v1.1.0) — Genos SHOULD enable it for production agent profiles.
- **In transit:** Cloud sync only for `write_through` non-secret cartridges; TLS via S3 endpoint (provider-dependent).
- **Access control:** Backend-only resolution; MCP/HTTP tools expose metadata/audit/proxy patterns, not plaintext.
- **Audit:** Secret resolution events and sync decisions logged without values (`cloud.log` / resolver audit log).
- **Validation:** Reject/flag credential-like material in non-secret kinds (existing `credentials` detection) and in Secret Domain value fields.

## 10. Migration and compatibility

- All existing cartridges remain readable. Missing `sync_policy` → derived default. Agent schema 1 → treated as schema 2 with null bindings on read, upgraded on write.
- Cloud sync behavior becomes **stricter** (safer): cartridges previously eligible by path but now policy-denied (e.g. agents defaulting to `never`) will stop syncing. Operators who explicitly want agent sync must set `sync_policy: write_through` intentionally — this is a deliberate safety change and must be called out in release notes.
- No data loss: policy denial skips sync; it does not delete local or remote objects.

## 11. Testing plan

- **Unit:** effective policy resolution (absent/type default/explicit), Secret Domain CRUD (metadata only), Agent schema v2 round-trip + schema 1 upgrade, resolver chain parsing/enforcement.
- **Integration:** `SyncEngine` push/pull/status refuses `never` for agent/secret/vault cartridges even when path-allowlisted; allows `write_through` memory cartridges; fail-closed on unreadable header.
- **Security:** no plaintext in Secret Domain storage/list output; resolver never logs values; credential-like content rejected in non-secret writes (existing) and in secret metadata where applicable.
- **Regression:** existing vault/agent/cloud/sync tests pass with new defaults accounted for (tests expecting agent/vault sync must be updated to set explicit policy or expectations).

## 12. Rollout

- **v1.2.0:** implement §8.1–8.3, core resolver helpers, CLI/MCP metadata tools, sync engine enforcement, docs.
- **Genos P0/P1:** consume Agent schema v2 + multi-vault/providers (available now) + SecretResolver prototype.
- **Genos P2:** adopt Secret Domain cartridge and policy-enforced Cloudflare sync end-to-end.

## 13. Open questions (to resolve during implementation/Genos integration)

1. **Agent sync default:** keep `agent` default `never` (safest) vs `write_through` for non-secret agent profiles? (Recommendation: `never` by default; explicit opt-in per agent.)
2. **Secret ref URI scheme:** canonical form for provider refs inside Secret Domain (`provider:1password:op://...` vs storing provider+ref fields separately). Structured fields are easier to validate; decide one canonical serialization.
3. **Secret Domain encryption envelope:** reuse vault v5 encrypted-entry format, agent SQAE file envelope, or a small dedicated envelope — pick the one with least new code and strongest reuse of audited primitives.
4. **Resolver location:** pure library in `sqac` vs Genos-only. Even if in `sqac`, document that plaintext resolution is backend-trusted-only and not exposed via MCP/HTTP.
5. **Allowed-tools enforcement:** schema-only in SQAC (v1.2) vs enforced by a SQAC-side policy helper; Genos orchestrator is the primary enforcement point.
6. **Offline conflict policy for Cloudflare non-secret sync:** last-writer-wins vs manual merge — remains a Genos/SQAC sync design choice (tracked in Genos docs).
