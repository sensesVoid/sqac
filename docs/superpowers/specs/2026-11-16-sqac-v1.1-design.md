# SQAC v1.1.0 Design — Feature Bundle

Date: 2026-11-16
Status: draft (pending approval)
Scope: Track C of the post-1.0 split. Wheels expansion (macOS/aarch64) is
Track B, a separate CI-only PR, and is explicitly out of scope here.

## Intent and why

v1.0.0 hardens what exists. v1.1.0 pays down the deferred list in one
additive release: encrypt agent state on request, let users hold more than
one vault, fetch vault keys from real secret managers instead of only the
OS keychain, publish docs as a site, and stop regressions before they
ship. User decision: everything listed lands in one version.

## Goals

- **G1 — Agent-cartridge encryption.** `AgentCartridge` files can be
  encrypted at rest with the vault's proven crypto stack
  (AES-256-GCM + keychain/Argon2id). Opt-in, never default.
- **G2 — Multi-vault.** Named vault files under `~/.sqacm/vaults/`,
  `--vault` CLI flag, active-vault pointer, and
  `vault:VAULT/NAME` reference syntax alongside today's `vault:NAME`.
- **G3 — External secret providers.** Vault master keys can live in
  1Password and Bitwarden via their CLIs (`op`, `bw`). Subprocess only,
  zero new Python dependencies.
- **G4 — Docs site.** MkDocs Material on GitHub Pages, nav assembled
  from README + existing `docs/` pages. Content already exists; this is
  packaging, not writing.
- **G5 — Blocking performance gate.** CI fails on >20% regression vs a
  recorded baseline (`experiments/PERF_BASELINE.json`, 5K-entry bench,
  ~30s on an ubuntu runner). Baseline refresh is a manual, documented
  release step (RELEASE.md).
- **G6 — Package hygiene.** `sqac/RESEARCH.md` →
  `docs/RESEARCH-unlimited-context.md`; `tests/bench_rack.py`,
  `tests/bench_skill_store.py`, `tests/poc_quant_encoder.py` →
  `experiments/`; update the ~3 docstring references.

## Non-goals

- No new crypto primitives — reuse `vault_crypto` as-is.
- Agent encryption is never default-on; plaintext agents stay first-class.
- No cloud secret-manager APIs (AWS/GCP/Azure/HashiCorp) — those need SDK
  dependencies or bespoke HTTP clients; deferred to a later release.
- No cartridge format schema bump beyond reusing the existing encrypted
  cartridge flag the vault format already carries.
- No changes to the SIMD/store hot paths.

## Anti-goals (failure modes)

- Secrets in memory cartridges (the credentials detector stays strict).
- Storing master keys anywhere except the chosen provider/keychain.
- A docs site that forks from `docs/` (one source of truth, one build).
- A perf gate that flakes on runner noise (tolerance + median-of-3
  required, or the gate loses trust and gets ignored).

## Constraints

- Zero new runtime dependencies (providers are subprocess CLIs; docs site
  is a repo concern, not a package concern).
- Backward compatible: existing plaintext agents and single default vault
  keep working unchanged; old vault refs (`vault:NAME`) keep resolving.
- Windows/macOS/Linux parity for every new CLI path (the `pwd` incident
  in hardening is the cautionary tale: lazy Unix-only imports get caught
  by users, not CI).

## Approaches considered

### Agent encryption
- **A1 (chosen): cartridge-level reuse.** Wrap agent save/load with the
  vault's encrypt/decrypt path (same header flag the vault format uses),
  master key in keychain under a distinct service name (`sqac-agent`).
  Smallest surface, proven code, no new format.
- A2 (rejected): agent-in-vault — store agent state inside a Vault
  cartridge. Conflates two features (agent lifecycle vs vault security)
  and breaks `AgentCartridge`'s direct file access.
- A3 (rejected): new encryption scheme for agents. Violates non-goal.

### Multi-vault
- **B1 (chosen): name-keyed vault files + active pointer.** Vaults are
  `<name>.sqac` under `~/.sqacm/vaults/`; `vault_active` pointer mirrors
  `agent_active`; refs gain an optional `VAULT/NAME` segment. Predictable,
  matches existing agent-active UX.
- B2 (rejected): single vault file with internal namespaces. One corrupt
  file loses everything; file-level isolation is the security boundary
  already tested (lock audits).

### Secret providers
- **C1 (chosen): CLI-wrapper providers.** `op read op://...` and
  `bw get password <id>` via subprocess; vault header stores the provider
  URI as the key source (`kdf: "provider"`, `provider_ref`). No Python
  deps; failure modes are CLI-not-installed / locked / denied — surfaced
  as actionable errors.
- C2 (rejected): HTTP clients per provider — new deps per provider,
  token management re-invented, and CLIs already handle auth.
- C3 (rejected): generic "external command" provider only — flexible but
  pushes UX work onto every user; the two named wrappers are the 80%.

## Decided (my calls, flag anything wrong)

- Version: **1.1.0** (additive, backward compatible).
- Providers: **1Password + Bitwarden CLI wrappers**; cloud APIs deferred.
- Agent encryption UX: `sqac agent create --encrypt` / `sqac agent encrypt`
  / `sqac agent decrypt` / `sqac agent key rotate`; default-off; plaintext
  load stays valid.
- Multi-vault UX: `sqac vault init/create/list/use <name>` +
  `--vault <name>` global flag; `vault:NAME` resolves in the active vault
  (compat), `vault:VAULT/NAME` explicit.
- Docs site: MkDocs Material, `mkdocs.yml` at repo root, GitHub Pages via
  gh-pages branch, deploy CI job on release tags only.
- Perf gate: `experiments/perf_gate.py`, 5K-entry bench, median of 3,
  >20% regression fails CI; baseline updated manually per release.
- Hygiene moves land first (pure moves + reference updates).

## Sequencing

1. G6 hygiene (isolated, zero risk)
2. G2 multi-vault (foundation: providers bind to named vaults)
3. G3 providers (needs G2's vault registry)
4. G1 agent encryption (reuses keychain patterns from G2/G3 work)
5. G5 perf gate (needs a recorded baseline; can start in parallel)
6. G4 docs site (last; nav final once docs settle)

## Left to the builder

- Exact `vault_crypto.aad()` wiring for per-vault AAD (the format already
  carries a vault name — verify it flows through multi-vault paths).
- `vault_active` pointer vs `--vault` flag precedence rules (flag wins).
- Error messages for missing/locked CLIs (include install hints).
- Test matrix: provider CLIs are mocked in tests (no real `op`/`bw` in CI);
  agent-encryption round-trip + wrong-key failure tests; multi-vault
  isolation tests (cross-vault ciphertext must fail AAD check).
- Wheels/docs-site CI wiring details (Track B owns wheels).
